# 와우클립

현재 진입점은 `WowClip.jsx`의 `/wowclip`이다. 기존 MainLayout과 팀의 인증·프로필·작품·시청 기록 구조를 재사용한다. 폴더 구성은 팀의 `home`·`my`처럼 기능 폴더 아래 컴포넌트와 SCSS를 나누는 방식에 맞췄다.

```text
wowclip/
├── WowClip.jsx              # 현재 목록·감상 진입점
├── components/              # 카드, 연속 감상, 댓글, 플레이어, 편집, 공용 UI
├── hooks/                   # useWowClipLibrary
├── data/                    # Firestore 저장/실시간 구독·트랜잭션
├── utils/                   # 표시·저장 데이터, 구간·자르기 계산, 해당 테스트
├── scss/                    # 와우클립 전용 스타일
├── pages/                   # 별도로 들어온 목록·상세·편집 화면 보존
└── README.md
```

## 현재 연결

- `App.jsx` → `WowClip.jsx` → `components/ClipCard` 또는 `components/ClipFeed`.
- 홈의 `WowClipSection` → 같은 카드와 저장소. 공개 클립을 공감·최신순으로 최대 8개 표시한다.
- 본편 `Watch` → `components/FullVideoClipButton` → 로그인 확인 → `components/ClipEditor` → Firestore 저장 완료 후 감상 화면. 비로그인은 로그인으로 안내하며 인증 확인 중에는 제작을 잠그고 로그아웃하면 열린 편집도 닫는다.
- 페이지 루트의 import 경로는 유지했다. 홈·Watch는 옮긴 모듈 경로만 변경했다.

## 동작

카드는 2:3 세로형이다. 와우클립 목록은 최소 270px에서 남는 가로 공간을 균등 분배하는 그리드이며, 640px 이하에서는 2열이다. 메인 섹션은 다른 메인 콘텐츠와 같은 Swiper로 한 줄 슬라이드를 구성한다. 메인 카드 폭은 282px이고 좁은 화면에서는 화면 폭에서 80px을 뺀 값까지 줄인다. 간격은 20px, 640px 이하에서는 12px이다. 화살표·마우스 드래그·터치 스와이프·키보드로 넘기며 루프나 자동 재생은 사용하지 않는다. 예시 작품·작성자·숫자를 채우지 않고 저장된 클립만 표시하며 빈 상태와 읽기 오류를 처리한다.

목록에는 인기순·최신순 정렬만 제공한다. 기간별 탭과 날짜 필터는 없으며 과거 링크의 `period` 값도 목록을 제한하지 않는다.

감상 화면은 세로 스크롤·방향키·이전/다음 버튼으로 저장된 클립을 이어 본다. 활성 클립의 플레이어 하나만 마운트하고 선택 구간을 반복한다. 하트, 댓글, 공유, 본인 클립 삭제를 제공한다. 감상 화면에는 제작 버튼이 없고 본편에서만 제작한다.

감상 정보 뒤의 그라데이션은 영상 하단 전체 폭에 적용해 텍스트 너비에서 사각형으로 끊기지 않는다. 풀영상 버튼과 작품 정보는 같은 32px 높이의 flex 행에서 정렬하며 좁은 화면에서는 항목 단위로 줄바꿈한다.

원본 시청 화면에서 선택한 시즌·회차와 API의 시즌 수를 편집 및 저장에 전달한다. 여러 시즌은 `시즌 2 · 7화`, 한 시즌은 `4화`, 스페셜은 `스페셜 · 2화`처럼 표시하고 영화는 회차를 붙이지 않는다. 원본 복귀 링크도 저장한 시즌·회차를 전달한다. 회차 정보가 없는 클립에는 작품 제목만 표시하며 임의로 1시즌 1화를 저장하거나 기존 데이터를 다시 쓰지 않는다. 표시·검증·원본 복귀 상태 생성은 `utils/clipSource.js`에 있다.

편집은 가로형 16:9와 세로형 9:16을 제공한다. 선택 버튼의 아이콘은 같은 36px 영역 안에 중앙 정렬하고 이름·비율 위치를 맞춘다. 작품명·회차는 클립 제목 입력 영역 바로 위에 표시하고 별도 영문 영상 설명은 표시하지 않는다. 편집 영상 하나에서 구간과 세로 자르기 영역을 확인하며 오른쪽에는 작품명·회차, 클립 제목·공유 설정을 표시한다. ‘구간과 화면 선택’ 문구 없이 영상 상단을 오른쪽 작품명·회차의 상단과 맞춘다. 구간 바를 움직이면 영상이 해당 시각을 따라가고 조절 후 선택 시작점부터 재생한다. 세로 선택 영역은 드래그·방향키로 옮기며, 화면 위치 슬라이더 손잡이의 중심은 영상 속 자르기 영역의 중심과 같은 x좌표를 이동한다. 트랙 너비와 양쪽 여백은 자르기 비율에서 계산하며, `layout`·`cropX`·구간 저장 방식은 유지한다.

댓글은 우측 패널 안에서 스크롤한다. 입력 박스는 대기·포커스·작성 중 모두 72px이며, 같은 입력창으로 답글을 쓰고 성공하면 일반 댓글로 돌아간다. 답글 연결선·접기/펼치기·인기순/최신순을 제공한다. 댓글 공감은 선/채움 엄지 아이콘으로 바뀌고 숫자 변화로 답글 위치가 움직이지 않게 폭을 확보한다.

스포일러 보호된 클립은 확인 전 실제 제목·장면·댓글·플레이어를 렌더링하지 않는다. 안전한 작품 이미지가 없으면 장면 썸네일로 대체하지 않는다. 제작 직후 본인의 확인 화면과 같은 페이지에서 이미 확인한 클립은 바로 연다.

## 데이터와 범위

- 영상과 작품 정보는 기존 TMDB/YouTube 결과를 전달받는다. 예시 이미지를 다운로드하지 않는다.
- 새 클립·댓글·공감은 기존 프로젝트 Firestore의 `wowClips`와 하위 컬렉션에 저장하고 실시간 구독한다. `src/service/wowClipService.js`가 기존 Auth/DB를 전용 repository에 연결한다. 작성자 UID는 현재 로그인 계정으로 검증하며 팀의 인증·프로필·작품 저장소와 Firebase 초기화는 변경하지 않는다.
- Firebase 연결 전 브라우저 클립을 표시하던 ‘기존 클립’ 메뉴와 ‘계정에 저장’ 이전 기능은 제거했다. 현재 목록·직접 링크·감상은 Firestore 클립만 사용한다. 예전 `localStorage['coupangplay.wowclip.v1']`는 읽거나 변경하지 않으며 자동 업로드도 하지 않는다.
- 새 서버 클립의 복사 링크는 같은 프로젝트를 사용하는 다른 기기에서도 조회할 수 있다. 공개 클립은 목록에, 링크 전용은 직접 링크와 본인 목록에 노출한다. 영상 자체는 YouTube 구간 참조이며 MP4 인코딩·업로드 기능은 없다.
- 댓글·공감·조회 기록은 별도 문서로 저장하고 집계는 트랜잭션으로 갱신한다. 댓글/답글은 서버 저장 성공 후에만 입력을 비우고 실패하면 내용을 보존한다. 조회 수는 현재 로그인 계정별 최초 재생 수다.
- 연결의 보안 규칙과 현재 실서버 검증 한계는 [Firebase 적용 안내](../../firebase/README.wowclip.md)에 있다. 현재 관리 인증이 HTTP 403이어서 새 규칙을 실제 서버에 배포하지 못했으며, 기존 팀 규칙 파일을 덮어쓰지 않았다.
- YouTube 기본 조작부는 숨기고 자체 조작부를 쓴다. YouTube의 제목·브랜드 표시 전체를 제거하는 기능은 아니다.

## 별도 화면 코드 보존

`pages/WowClipGallery.jsx`, `pages/WowClipDetail.jsx`, `pages/WowClipCreate.jsx`는 현재 App 라우트나 본편 제작 버튼에서 사용하지 않는다. 이 코드는 별도 `src/components/wowclip/clipStorage.js`와 `coupang-wowclip-v2` 형식을 사용한다. 현재 저장소와 자동으로 합치거나 라우트를 교체하지 않았다. 기존 샘플 데이터와 Firebase 댓글 연동도 실사용 흐름에 연결하지 않았다.

`WowClipCreate`는 기존 WowClip 파일 뒤에 붙어 있던 편집 모듈을 분리해 이름만 구분한 것이다. 기존 코드의 삭제나 기능 통합 없이 보존했다. 편집용 SCSS도 `scss/WowClipCreate.scss`로 분리해 해당 화면에서만 불러온다. 이 세 파일에 남아 있던 기존 lint 진단은 실사용 코드의 검수와 구분한다.

## 검증

```sh
node --test src/page/wowclip/utils/*.test.js
npx eslint src/page/wowclip/WowClip.jsx src/page/wowclip/components src/page/wowclip/hooks src/page/wowclip/utils src/page/home/components/WowClipSection.jsx
npm run build
```

Firestore/컴포넌트 통합 검수는 `scripts/wowclip-tests/run.ps1`을 사용한다. 기본 Node 테스트 자동 검색에 에뮬레이터 의존 검사가 섞이지 않도록 별도 scripts 폴더에 두었다.

2026-11-06 폴더 이동 후 문법·경로·SCSS 컴파일 및 메모리 전용 브라우저 검수를 수행했다. 자세한 결과는 작업 폴더의 `output/wowclip-organization-2026-11-06/`에 있다. 브라우저 검수의 가상 클립·댓글은 실제 사용자 저장소에 넣지 않았다.

조직 방식 참고: [React 컴포넌트 분리](https://react.dev/learn/importing-and-exporting-components), [기능별 관련 코드 배치](https://redux.js.org/style-guide/#structure-files-as-feature-folders-with-single-file-logic). Redux 도입이나 전체 프로젝트 구조 변경을 의미하지 않는다.
