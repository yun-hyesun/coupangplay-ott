# 마이팀 인기영상 공용 저장소

마이팀 인기영상은 `/api/my-team-videos`에서 SQLite에 저장된 목록만 읽습니다. 방문·새로고침·다시 조회·팀 선택으로 YouTube 검색을 실행하지 않습니다. 확인된 쿠팡플레이 스포츠 공식 채널 일반 영상만 기존 팀 판별 로직을 거쳐 팀당 조회수 상위 4개를 표시합니다. 동영상 탭의 날짜/팀 검색과 스포츠 메인의 기존 API는 별도입니다.

## 로컬 실행

- Node.js 22.13 이상(권장: 프로젝트에서 확인한 Node.js 24).
- 기존 `.env.local`의 서버용 `YOUTUBE_API_KEY` 사용. 기존 `VITE_YOUTUBE_API_KEY`도 호환합니다. 키를 DB나 브라우저 응답에 저장하지 않습니다.
- `npm run dev`가 공용 수집 작업을 자동 시작합니다. 서버가 실행 중일 때 새 업로드와 조회수는 12시간 간격으로 갱신하며, 1분마다 실행 여부를 확인합니다.
- DB는 프로젝트의 `.data/youtube-catalog.sqlite`입니다. Git에서 제외하며 서버 재시작 후에도 유지합니다. 경로를 변경하려면 서버 환경변수 `YOUTUBE_CATALOG_DB`에 영구 저장 경로를 지정합니다.
- `npm run videos:sync`: 제한된 분량을 한 번 수집/갱신하고 건수·진행 상태 출력.
- `npm run videos:worker`: 개발 서버 없이 수집 작업을 계속 실행.

## 수집·갱신 방식

영상 정보는 **최대 5,000건**만 보관합니다. 최근 후보용으로 최대 500건을 우선 확보하고, 나머지는 리그별로 조회수가 높은 확인 영상을 고르게 보관합니다. 초과 시 확인된 쇼츠·조회 불가 영상·우선순위가 낮은 정보를 먼저 정리합니다. 인기영상 순위는 이 보관 목록을 기준으로 합니다.

새 후보는 먼저 API로 정보를 확인한 뒤 기존 목록과 같은 트랜잭션에서 병합·정리합니다. 저장이 확정된 시점에는 5,000건을 넘지 않으며, 한도를 채웠어도 새 영상의 추가와 조회수 갱신은 계속됩니다. 정리된 영상의 ID 전체를 별도로 누적하지 않습니다.

1. `channels.list`로 공식 채널의 업로드 재생목록 ID를 한 번 확인해 저장합니다.
2. `playlistItems.list`로 과거 목록을 페이지당 50개씩 확인하되 보관 상한을 지킵니다. 매 페이지의 다음 커서를 DB에 저장하므로 종료 후 이어집니다. 기본 실행당 최대 20페이지이며 다음 실행에 나머지를 이어갑니다.
3. `videos.list`에 ID를 최대 50개씩 묶어 제목·썸네일 URL·시간·조회수·플레이어 비율 정보를 갱신합니다. 실행당 최대 20묶음, 영상별 최소 12시간 간격입니다(메타데이터 형식 변경 시 한 번 갱신). 삭제/비공개/다른 채널로 확인된 영상은 노출 목록에서 제거합니다.
4. 3분 초과 영상과 API의 명시적인 `player.embedWidth/embedHeight`로 가로 비율이 확인된 영상은 일반 영상으로 확인합니다. 이 치수는 화면 비율을 아는 경우에만 제공됩니다. 썸네일이나 기본 iframe HTML의 크기로 추정하지 않습니다. 3분 이하 세로·정사각형·비율 미확인 영상은 기존 쇼츠 확인기를 사용하며, 확인하지 못한 영상은 일반 영상으로 추정하지 않습니다. 리그별 조회수가 높은 후보를 고르게 확인합니다(실행당 최대 4묶음, 묶음당 50개, 시간 제한 적용). 분류 결과는 공유 저장하고 미확인 영상은 지연 후 재시도합니다. 상위 4개 후보보다 조회수가 높은 미확인 영상이 있으면 확인 중이라는 안내를 표시합니다.
5. 최초 확인 중에도 보관된 영상은 표시합니다. 업로드 목록 확인이 끝나기 전에는 이전 영상을 수집 중이라는 안내를 표시합니다. 이후에도 순위 범위는 보관된 최대 5,000건입니다.
6. 신규 업로드 조회용 커서와 과거 확인 커서를 분리합니다. 최신 업로드 경계 한 건도 별도로 기록하여 그 영상이 보관 목록에서 빠져도 경계를 잃지 않습니다. 이후 새 업로드는 기존 경계까지만 확인합니다. 조회수는 보관한 ID로 갱신하므로 팀별 검색이 필요 없습니다.

작업은 프로세스 내 중복 요청을 합치며 DB 임대로 여러 작업자의 동시 실행도 방지합니다. API 호출량은 DB에 태평양 시간 날짜별로 기록하며 이 작업의 기본 예산은 하루 2,000회입니다. 다른 기능이 쓰는 할당량까지 보장하는 수치는 아닙니다. 예산/제공자 한도 초과 시 호출을 멈추고 저장된 목록을 유지하며 재시도 시간을 저장합니다. 요청 로그나 오류 응답에 API 키를 포함하지 않습니다.

API 데이터는 30일 안에 재조회하며, 갱신되지 못한 30일 이상 데이터는 화면에서 제외하고 저장 메타데이터도 지웁니다. 동영상 파일을 다운로드하지 않고 기존 내부 플레이어로 재생합니다.

## 배포

현재 저장소는 **쓰기 가능한 영구 디스크가 있는 단일 Node 서버/로컬 PC용**입니다. 정적 `vite preview`는 API 서버가 아닙니다. 운영에서는 API와 작업자가 같은 `YOUTUBE_CATALOG_DB`를 사용하고 작업자를 계속 실행해야 합니다. Vercel 등 임시 파일시스템만 제공하는 서버리스 환경에 그대로 배포하면 DB 지속성이 보장되지 않으므로, 그 환경에서는 공용 영구 DB와 스케줄 작업으로 저장소를 교체해야 합니다. 여러 호스트 사이에 SQLite 파일을 복사하거나 각자 DB를 만들면 공용 예산·목록이 분리되므로 지원하지 않습니다.
